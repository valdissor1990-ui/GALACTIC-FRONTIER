# Аудит DeepSeek validate_fleet.py v2.2

Дата: 12.11.2026  
Статус: **статический аудит; Blender не запускался; PASS не заявляется.**

## Итог

\`validate_fleet.py v2.2\` нельзя подключать к текущему состоянию GALACTIC FRONTIER без адаптации контракта. Файл написан под отдельный пакет \`generators/ship_base.py\` + \`generators/build_all.py\`, тогда как фактический репозиторий пока использует три генератора в \`scripts/blender/\` и плоскую структуру результатов. При прямом запуске валидатор будет давать ложные FAIL ещё до содержательных проверок.

## Блокирующие несовпадения с репозиторием

1. **Импорт отсутствующего модуля.** В текущем репозитории нет \`generators/ship_base.py\`; v2.2 импортирует \`ship_base\` из каталога \`generators/\`.
2. **Несовпадение путей.** Валидатор ожидает \`build/blend\`, \`build/glb\`, \`build/renders\`. Текущие генераторы пишут в \`build/blender/\` (или в переданный \`--output-dir\`) и используют имена \`player_fighter\`, \`enemy_fighter\`, \`heavy_fighter\`, \`bomber\`, \`cargo_hauler\`, \`frigate\`, \`cruiser\`.
3. **Несовпадение идентификаторов.** В \`SHIPS\` валидатора перечислены \`PlayerFighter\`, \`RaiderInterceptor\`, \`AegisHeavy\`, \`BastionBomber\`, \`MuleHauler\`, \`VanguardFrigate\`, \`LeviathanCruiser\`. Это не имена файлов текущего генератора.
4. **Неверный поиск корня.** \`_find_ship_by_exact_name()\` ищет объект типа \`MESH\` с именем класса, а текущие генераторы создают корневой \`EMPTY\`: \`GF_PlayerFighter_Root\`, \`GF_RaiderInterceptor_Root\`, \`GF_heavy_fighter_Root\` и т. д. Геометрия находится в дочерних MESH. Поиск корня нужно строить по отдельному root-контракту, а не по имени одного mesh.
5. **Hardpoint-контракт отсутствует в текущих генераторах.** В некоторых моделях есть визуальные детали, названные hardpoint, но это не гарантирует наличие экспортируемых \`EMPTY\`-узлов с контрактными именами. Для текущего набора нужно сначала добавить функциональные Empty hardpoints и только затем требовать их от валидатора.

## Логические дефекты v2.2, которые остаются даже при правильном пакете

1. В \`_compute_comparison()\` \`structure_valid\` считает иерархию проблемной только при \`parent_ok is False\`. Значение \`None\` означает, что родитель не удалось проверить, но сейчас оно не блокирует \`structure_valid\`. Для строгой структурной проверки допустимо только \`parent_ok is True\`.
2. \`structure_valid\` не включает \`duplicate_bases_blend\` и \`duplicate_bases_glb\`. Отдельные проверки выше добавляют critical, но поле \`match\` может при этом показывать \`true\`, что противоречит его заявленному смыслу.
3. \`check_png()\` при ошибке чтения пикселей добавляет warning и возвращает управление, но не добавляет запись в \`failed_checks\`. Поэтому \`summary.completeness\` может остаться \`complete\`, хотя содержательная проверка изображения не была выполнена.
4. \`_classify_children()\` проверяет только прямых потомков root. Вложенные Empty-узлы могут не попасть в классификацию подозрительных/ошибочных hardpoints.
5. \`_collect_all_hp_any_type()\` ищет hardpoints глобально по \`bpy.data.objects\`, не ограничивая их деревом выбранного корабля. При наличии дополнительных объектов в сцене возможны посторонние совпадения.
6. \`ships_failed\` считает только \`r.critical\`; в \`--strict\` корабль с warnings получает статус \`failed\`, но в агрегатном счётчике не учитывается.
7. \`_sample_grid()\` не проверяет конечность полученных RGB-значений. NaN в \`img.pixels\` может попасть в статистику и сделать сравнения порогов недостоверными.
8. Пороговые значения PNG и сравнение силуэтов по трём отношениям AABB не являются доказательством визуального качества. Это эвристический фильтр; его нужно калибровать на реальных рендерах. Сходство AABB не доказывает одинаковый силуэт, а различие AABB не доказывает уникальность формы.

## Что уже сделано в текущей рабочей ветке

- Исправлена фатальная ошибка в \`build_fleet_expansion.py\`: \`make_materials()\` возвращает 6 материалов, а \`turret()\`, \`engine()\` и \`detail_panels()\` распаковывали только 5.
- Увеличена дистанция камеры студийного рендера для крупных кораблей, чтобы снизить риск обрезания Leviathan/Vanguard.
- Добавлен отдельный \`validate_fleet_assets.py\`, который работает с текущими slug-именами и проверяет геометрию именно внутри \`GF_*_Root\`, не включая студийный пол/камеры/свет в \`.blend\`.
- Добавлен Godot smoke test для загрузки и инстанцирования семи GLB.

## Ограничение фактической проверки

Blender 4.5.16 и Godot 4.7.2 отсутствуют в локальном runtime. GitHub Actions workflows подготовлены, но файлы workflow отсутствуют в default branch \`main\`; GitHub не запускает \`pull_request\` workflow, пока workflow-файл не присутствует в default branch. Коммитить workflow прямо в \`main\` или мержить без разрешения нельзя. Поэтому генерация 5 дополнительных моделей, GLB-импорт, тесты и новые игровые скриншоты пока не подтверждены. Ни один из этих этапов не помечен PASS.
